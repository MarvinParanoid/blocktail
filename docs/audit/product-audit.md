## 1. Что реально реализовано

Подтверждено чтением кода и запуском:

- Индексация ETH (external), internal ETH и ERC-20 через `alchemy_getAssetTransfers`, идемпотентно по `uniqueId` (`UNIQUE(chain_id, event_key)` + upsert).
- Пер-аккаунтные водяные знаки (`synced_to_block`, `indexed_from_block`), пересканирование последних `REORG_DEPTH` блоков, удаление пропавших событий только после полностью успешного цикла.
- Owned/watched; итог портфеля только по owned; одна строка `Main → Cold` для переводов между своими кошельками; точка зрения зависит от scope.
- Балансы ETH и ERC-20, перечитываются только у «двигавшихся» кошельков + полный проход раз в `BALANCE_REFRESH_SECONDS`.
- Оценка в USD (Alchemy Prices), защита от «одного актива на весь портфель», фильтр dust/unverified/impostor, вендоренный token list.
- Лента: группировка по дням и по транзакции, keyset-пагинация, фильтры (кошелёк, scope, направление, актив, поиск), «показать скрытое», «загрузить ещё N дней».
- Transaction inspector с комиссией/газом по запросу.
- Добавление/переименование/удаление кошельков из UI (только `source = 'ui'`), CSRF-проверка по `Sec-Fetch-Site`/`Origin`.
- Необязательный HTTP Basic auth, `/healthz`, JSON API (`/api/activity|accounts|portfolio|status`).
- Docker: non-root, loopback-публикация порта, named volume, healthcheck.

## 3. Подтверждённые дефекты

### D-01 · P0 · API-ключ Alchemy утекает в UI и JSON API

- **Где:** `app/chains/ethereum/alchemy.py:114-125` (`_rpc` превращает `httpx.HTTPStatusError` в `ProviderError(... {last_error})`), `app/sync.py:139, 175-176` (`record_failure(str(exc))`), `app/web/format.py:129-130` (`detail = status.last_error`), `app/web/templates/_status.html` (рендер `status.detail`), `app/web/routes.py` `api_status` (`last_error`). То же в `app/prices.py:83-90`, но там только в лог.
- **Воспроизведение:** провайдер отвечает статусом не из `_RETRY_STATUS` (401 на отозванный/неверный ключ, 400, 404, 413). `response.raise_for_status()` бросает `HTTPStatusError`, в тексте которого полный URL `https://eth-mainnet.g.alchemy.com/v2/<KEY>`.
  ```python
  prov = AlchemyProvider(build_url(KEY), client=httpx.AsyncClient(
      transport=httpx.MockTransport(lambda r: httpx.Response(401, json={}))))
  # create_app(... provider=prov), run_once()
  KEY in client.get("/").text            # True
  KEY in client.get("/status").text      # True
  KEY in client.get("/api/status").text  # True
  ```
- **Ожидается:** ключ не появляется нигде за пределами процесса, как обещает README.
- **Фактически:** ключ в красной строке статуса на каждой странице (опрос каждые 5 с), в `/api/status` и в логах.
- **Почему важно:** по умолчанию auth выключен. Любой, кто видит страницу (через туннель, общий tailnet, скриншот в issue), получает ключ и квоту. Тест `test_is_read_only_and_leaks_no_secrets` этот путь не покрывает: он проверяет только здоровое состояние.
- **Решение:** (1) в `_rpc`/`_request` не включать текст исключения httpx в сообщение: писать `method: HTTP 401`, `method: ConnectError`, `method: timeout`; (2) страховка на выходе: `redact()` в `record_failure` и в логгере, заменяющий `settings.alchemy_api_key` и путь `/v2/...` на `***`; (3) 401/403-без-ретрая показывать человеческим текстом («provider rejected the API key»).
- **Проверка:** тест по сценарию выше для 400/401/404 и для `ConnectError`; тест, что `last_error` и HTML не содержат ни ключа, ни подстроки `/v2/`; тест на логи через `caplog`.

### D-02 · P1 · Удалённый из UI кошелёк продолжает жить в общей ленте

- **Где:** `app/web/routes.py:_scope_ids` (scope «All» → `None` → без фильтра по аккаунтам), `app/db.py:_activity_filters` (`direction=in` → `to_account_id IS NOT NULL`), `app/db.py:relink_accounts` (не смотрит на `active`), `_ACTIVITY_SELECT` (join по `accounts` без `active`).
- **Воспроизведение:** добавить кошелёк через `+ Add wallet`, дождаться индексации, удалить через меню.
  ```text
  before remove, rows in All: 1
  after remove,  rows in All: 1  [('Temp', 'in', '7')]
  wallet listed in /api/accounts: False
  direction=in rows: 1
  ```
  Так же ведут себя кошельки, удалённые из `wallets.yml`.
- **Ожидается (README):** история сохраняется, но не показывается; при повторном добавлении возвращается.
- **Фактически:** строки остаются в «All activity» с именем удалённого кошелька, считаются «своими» в фильтрах IN/OUT и в схлопывании `A → B`, а в сайдбаре кошелька уже нет. `sent_asset_ids()` тоже учитывает неактивные аккаунты, то есть удалённый кошелёк продолжает «ручаться» за токены.
- **Почему важно:** лента перестаёт соответствовать списку наблюдаемых адресов; пользователь видит «IN · Temp», а кошелька Temp в интерфейсе нет.
- **Решение:** одно правило «неактивный аккаунт — то же, что неизвестный адрес» для чтения: либо `relink_accounts()` привязывает только `active = 1`, а `add_account` вызывает relink при восстановлении; либо фильтр «All» = все **активные** id, и join в `_ACTIVITY_SELECT` с `AND fa.active = 1`. Первый вариант проще и автоматически чинит направление, схлопывание и `sent_asset_ids`. Строки, где ни одна сторона не активна, в «All» скрывать.
- **Проверка:** тест «add → sync → remove → `/api/activity` пуст, IN/OUT пусты; re-add → строки вернулись без нового бэкфилла»; тест для config-кошелька, удалённого из YAML.

### D-03 · P1 · Скрытый impostor-токен с котировкой входит в итог

- **Где:** `app/web/format.py:build_portfolio` (`token_value += value` для каждого оценённого не-native актива, вычитаются только `implausible`, но не `hidden`), `build_wallets` (сумма в сайдбаре тем же способом).
- **Воспроизведение:** у кошелька ETH ($3,000), USDC ($1,000) и токен с тикером `USDT` по чужому контракту ($5,000 по котировке).
  ```text
  total: $9,000 | hidden: 1 | excluded: []
  sidebar Main: $9,000
  ```
- **Ожидается:** то, что приложение назвало подделкой и спрятало, не входит в сумму. Правило «impostor — самое жёсткое, что делает приложение» из ARCHITECTURE.
- **Фактически:** токен скрыт из списка, но $5,000 сидят в итоге, и пользователь не видит, откуда они.
- **Почему важно:** спам с «тикером-деньгами» и фейковым пулом — ровно тот кейс, ради которого есть фильтр. Сумма $5k меньше 90%, поэтому защита `VALUE_MAX_SHARE_PERCENT` не срабатывает.
- **Решение:** итог = сумма видимых (не hidden) и не excluded активов; hidden-dust < $1 на итог практически не влияет, его можно исключать по тому же правилу. Сайдбар и панель должны использовать одну функцию (сейчас логика продублирована в `build_wallets` и `build_portfolio`).
- **Проверка:** тест на сценарий выше: total = $4,000 в панели и в сайдбаре; тест, что при «Show hidden tokens» итог не меняется.

### D-04 · P1 · Временный сбой метаданных токена → итог портфеля в триллионах

- **Где:** `app/chains/ethereum/alchemy.py:_fetch_token_meta` (при ошибке кладёт в процессный кеш `(stub, 0)` и больше не повторяет), `get_token_balances` → `Balance(... decimals=0)`, `app/db.py:get_or_create_asset` (новый актив создаётся с `decimals=0`), `implausible_assets` (известные токены никогда не исключаются).
- **Воспроизведение:**
  ```text
  first  (provider 503 on getTokenMetadata): 0x2260…c599 decimals=0
  second (provider OK again):                0x2260…c599 decimals=0   <- закешированный сбой
  portfolio with 1 WBTC: $6,000,000,003,000  [('0x2260…c599', '100,000,000', '$6,000,000,000,000')]
  ```
  Реальный путь: кошелёк, добавленный с уже имеющимся WBTC без переводов в окне бэкфилла, плюс 403/503 от Alchemy на один из ~200 параллельных запросов метаданных. README сам говорит, что Alchemy отвечает 403 на всплески.
- **Ожидается:** неизвестные decimals — «оценить нельзя», а не «decimals = 0».
- **Фактически:** WBTC стоит $6 трлн и защищён от guard'а как известный токен. Исправляется само только после рестарта процесса.
- **Решение:** не кешировать неудачу (или кешировать с коротким TTL); при неизвестных decimals возвращать `decimals=None` и не оценивать актив; известным токенам брать decimals из вендоренного token list (там они есть) до запроса метаданных.
- **Проверка:** тест провайдера «503 → OK»: второй вызов делает новый запрос; тест портфеля: актив с неизвестными decimals идёт в «unpriced», а не в итог; тест, что WBTC из token list получает 8 decimals без RPC.

### D-05 · P1 · «Load N more days» — синхронизация в HTTP-запросе без ограничений

- **Где:** `app/web/routes.py:load_older_history` (`await ctx.indexer.run_once()` прямо в обработчике), `app/db.py:request_history_from`.
- **Воспроизведение:** три POST подряд на `/history/older`:
  ```text
  click 0: floor=21685700  provider calls in request=6
  click 1: floor=21678500  provider calls in request=6
  click 2: floor=21671300  provider calls in request=6
  ```
  Каждый клик опускает пол ещё на `BACKFILL_DAYS` навсегда и запускает **полный** цикл (все кошельки, оба направления) параллельно фоновому `run_forever`. Блокировки между циклами нет.
- **Ожидается:** один фоновой цикл за раз; запрос быстро возвращается и показывает прогресс; глубина ограничена.
- **Фактически:** (а) два цикла одновременно делят квоту и SQLite; (б) для активного кошелька 90 дней — это минуты, а nginx по умолчанию рвёт запрос через 60 с, и пользователь видит ошибку при реально идущей работе; (в) повторные клики и вкладки множат циклы; (г) `requested_from_block` «липкий»: если глубокий цикл падает, каждый следующий фоновой цикл снова сканирует всю глубину по всем кошелькам.
- **Решение:** `asyncio.Lock` (или single-flight) вокруг `run_once`; эндпоинт только записывает запрос и будит индексатор (`Event`), а UI показывает «indexing older history… (block X)» через тот же опрос статуса. Ограничить один запрос в работе и, по желанию, максимальную глубину настройкой.
- **Проверка:** тест: два параллельных `/history/older` и фоновой цикл → провайдер видит один цикл; эндпоинт отвечает < 1 с; статус показывает прогресс.

### D-06 · P1 · Деплой без страховки

- **Где:** `scripts/deploy.sh`.
- **Сценарий (Code):** скрипт делает `tar .` рабочего дерева с исключениями и отправляет в `/root/...` по ssh, затем `docker compose build && up --force-recreate`. Миграции применяются при старте.
- **Фактически:** (а) уезжают незакоммиченные и неотслеженные изменения: проверка «allowed» смотрит только на имена верхнего уровня; (б) тесты перед отправкой не запускаются; (в) бэкапа SQLite перед стартом новой версии (и миграций) нет; (г) после `up` не проверяются `healthz` и запуск, ошибка видна только в `docker compose logs`; (д) отката нет: предыдущий образ перезаписан тегом `blocktail:0.1.0`.
- **Почему важно:** миграции необратимы по дизайну («never destructive»), но кривая миграция или код без неё на рабочей БД без бэкапа — это потеря истории, которую придётся перебэкфиливать квотой.
- **Решение (минимальное, без новой инфраструктуры):** отказ при грязном `git status` (или явный флаг `--dirty`); `pytest -q` перед отправкой; `git archive HEAD` вместо `tar .`; на сервере перед `up` — `sqlite3 .backup` в `/data/pre-deploy-<sha>.db` (хранить последние N); после `up` — цикл ожидания `healthz` до 60 с, при провале сообщить и показать хвост логов; тегировать образ коротким SHA, чтобы откат был `docker compose up` с предыдущим тегом.
- **Проверка:** прогон на тестовом хосте; ручной откат по инструкции в README.

### D-07 · P2 · История удалённого кошелька в окне reorg стирается

- **Где:** `app/sync.py:_prune` + `app/db.py:known_event_keys` (выбирает все события окна независимо от аккаунта, а `observed` содержит только активные).
- **Воспроизведение:** добавить кошелёк, дождаться события, удалить кошелёк, дождаться следующего цикла: `activities = 0, pruned = 1`.
- **Ожидается:** «Its indexed history is kept» (текст подтверждения удаления в UI).
- **Решение:** ограничить `known_event_keys` событиями, у которых хотя бы одна сторона — активный аккаунт (или пересечение с отсканированными адресами).
- **Проверка:** тест из воспроизведения, ожидается `pruned = 0`.

### D-08 · P2 · Сбой балансов останавливает индексатор для всех

- **Где:** `app/sync.py:run_once` строки 188-200: при исключении в `_refresh_balances` выход до `mark_synced`/`record_success`.
- **Воспроизведение:** `fail_balances_with = RuntimeError(...)`; head растёт на 50 блоков за цикл:
  ```text
  cycle 0: scan from=21000093 span=57
  cycle 3: scan from=21000093 span=207   err='balance refresh failed: ...'
  ```
- **Фактически:** переводы уже сохранены, но водяной знак стоит, окно скана растёт с каждым циклом, статус красный «error», хотя лента свежая. Один «тяжёлый» кошелёк (таймаут `getTokenBalances`) блокирует продвижение для всех.
- **Решение:** продвигать водяной знак после успешного сохранения переводов; ошибку балансов хранить отдельно (`balances_error`), показывать янтарной строкой «balances not refreshed: …», а не состоянием error. Ретраить только неудавшиеся кошельки.
- **Проверка:** тест: при падающих балансах `last_synced_block` растёт, `state != "error"`, отдельный признак виден в UI и в `/api/status`.

### D-09 · P2 · Reorg во время простоя не вычищается

- **Где:** `app/sync.py:_prune`: `prune_from = max(from_block, head - reorg_depth)`.
- **Воспроизведение:** событие в блоке head-1 сохранено → приложение остановлено → цепь переорганизовалась и ушла на 500 блоков вперёд → старт. Пересканирование началось с 21000093 (включает блок события), но удаление ограничено последними 8 блоками: `pruned: 0, left: 1 (orphan kept forever)`.
- **Почему важно:** редкий случай (нужен простой в момент reorg), но последствие — вечная фантомная строка. Пересканированный диапазон и так целиком авторитетен для активных кошельков.
- **Решение:** `prune_from = from_block` (диапазон, который реально пересканирован для всех аккаунтов), с учётом D-07.
- **Проверка:** тест из воспроизведения.

### D-10 · P2 · Нет HTTP security-заголовков

- **Где:** `app/main.py` (ни middleware, ни заголовков).
- **Воспроизведение:** `GET /` → заголовки: только `content-length`, `content-type`.
- **Почему важно:** страницу можно встроить во фрейм (clickjacking на «Remove» / «Add wallet»: запросы из фрейма — same-origin, поэтому CSRF-проверка их пропускает); нет `nosniff`; ссылки на Etherscan уходят с полным `Referer`, включая `?q=<адрес>`.
- **Решение:** небольшой middleware: `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline'` (inline-скрипты и `onclick` сейчас есть; ужесточать поэтапно), `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Opener-Policy: same-origin`. HSTS не ставить: TLS терминирует прокси.
- **Проверка:** тест на заголовки; ручная проверка, что htmx и inline-обработчики работают с CSP (консоль без нарушений).

### D-11 · P2 · CSRF-проверка доверяет `same-site`

- **Где:** `app/web/routes.py:_same_origin` (`site in {"same-origin", "same-site", "none"}`).
- **Воспроизведение:** `POST /history/older` с `Sec-Fetch-Site: same-site` → 200.
- **Почему важно:** при размещении на `watch.example.com` любой другой поддомен `*.example.com` (блог, preview-деплой) может делать POST от имени пользователя, и браузер приложит basic-auth.
- **Решение:** принимать только `same-origin` (и `none` для прямой навигации/curl).
- **Проверка:** обновить `test_loading_older_history_is_not_open_to_other_sites` и аналоги для `/wallets*`.

### D-12 · P2 · Документация расходится с кодом

См. таблицу «Расхождения» в разделе 1, п. 3–8. **Решение:** одна правка README (env-таблица, формула расхода с учётом политики балансов и метаданных, честная оговорка «оценка, сверить с прайсом»), `.env.example` без дублей, правка комментариев в compose и `routes.add_wallet`. **Проверка:** тест, сверяющий ключи `load_settings()` с таблицей README и `.env.example` (дешёвый способ не допустить дрейфа).

### D-13 · P2 · Производительность на больших объёмах

- **Замер** (синтетика, 3 кошелька, `TestClient`, лучшее из 3):

  | Эндпоинт | 20k / 500 активов | 200k / 3000 активов |
  | --- | --- | --- |
  | `/` | 138 ms | **814 ms** |
  | `/activity` (опрос каждые 15 с) | 95 ms | 223 ms |
  | `/activity?q=0xab` | 33 ms | 263 ms |
  | `/dust-note` | 19 ms | 255 ms |
  | `/summary`, `/wallets` (каждые 30 с) | 8–10 ms | 109–110 ms |
  | `/status` (каждые 5 с) | <1 ms | 1 ms |

- **Причины (Code):** `_relevance()` (полный проход по `assets` + `looks_forged` + `sent_asset_ids`) вызывается ~5 раз на `/`; `_counts` делает три `COUNT(*)` с `LIKE` и `CAST(amount_raw AS REAL)`; `/status` в фоне продолжает опрос и в скрытых вкладках.
- **Оценка:** для личных кошельков (тысячи строк) незаметно; для watched-китов с сотнями тысяч переводов — ощутимо. Не срочно.
- **Решение:** вычислять `Relevance`/`unrecognised` один раз на запрос (или кешировать до следующего цикла индексатора: данные меняются только там); приостанавливать `every 5s` при `document.hidden`.
- **Проверка:** тот же бенчмарк, цель `/` < 300 ms на 200k.

### D-14 · P2 · Внешний мониторинг не видит, что синхронизация встала

- **Где:** `app/web/routes.py:healthz` — при включённом auth отвечает только `{"status":"ok"}`, а `/api/status` закрыт auth.
- **Почему важно:** «не путать liveness и provider outage» — правильное решение, но сейчас нет **никакого** сигнала без пароля: Uptime Kuma или healthchecks не узнают, что лента не обновлялась сутки.
- **Решение:** отдавать в `/healthz` и при auth неконфиденциальные поля `sync_state` (`ok|lagging|stale|error|starting`) и `last_success_age_s`, оставив HTTP 200; либо `GET /healthz?strict=1` → 503 при `stale`/`error` для внешнего монитора, не для Docker healthcheck.
- **Проверка:** тесты на оба режима.

### D-15 · P2 · Hardening контейнера и CI

- **Compose:** нет `read_only: true` + `tmpfs: /tmp`, `cap_drop: [ALL]`, `security_opt: [no-new-privileges:true]`, лимитов памяти. Приложение пишет только в `/data`, поэтому всё это включается без изменения кода.
- **Dockerfile:** база `python:3.13-slim` по тегу, без digest; `pip install` без `--require-hashes`. Для self-hosted приемлемо, но стоит указать в README, как обновлять базу.
- **CI:** `actions/checkout@v4`/`setup-python@v5` по тегу, не по SHA; нет `permissions: contents: read`; нет `pip-audit`; ruff в CI 0.14.5, локально 0.16.5; нет Dependabot для pip, actions и docker; job `image` проверяет только отказ без ключа, но не реальный старт с `healthz`.
- **Решение:** перечисленное по пунктам; smoke-тест: `docker run` с `ALCHEMY_URL=http://127.0.0.1:9` и минимальным `wallets.yml` → `healthz` = 200, `sync_state=error`.

### D-16 · P2 · Цены в ленте для активов, которых больше нет на балансе

- **Где:** `app/sync.py:_refresh_prices` (оценивает только `held_assets`), `app/db.py:replace_prices` (старые строки не трогаются), `build_activity` (берёт любую найденную цену без возраста).
- **Сценарий (Code):** токен продан полностью → его цена больше не обновляется, но строки ленты показывают «$ value» по цене месячной давности, без пометки о возрасте. От этой же цены зависят пороги dust (`_dust_thresholds`). Обратный случай: токен, который пришёл и ушёл между обновлениями цен, никогда не оценивается и, если его нет в token list, попадает в «unverified», включая собственный исходящий перевод.
- **Решение:** при рендере не показывать `value` строки, если цене больше `stale_after` (или показывать приглушённо с тултипом «price N days old»); подпись колонки и тултип «at current price» (см. U-раздел).
- **Проверка:** тест: цена старше порога → у строки нет `value_text`.

## 4. Что работает хорошо и проверено

- **Идемпотентность и дедупликация.** Ключ `uniqueId`, upsert, одинаковая строка из обоих сканов перевода между своими кошельками. Повторные циклы и рестарт дублей не дают (тесты + собственный прогон).
- **Reorg в штатном режиме.** Событие, пропавшее из окна, удаляется (контрольный прогон D-09A: `pruned: 1`); ниже окна ничего не удаляется; удаление только после полностью успешного цикла.
- **Точная арифметика.** Нигде нет float для сумм (`Decimal` с динамической точностью, `rawContract.value`); `format_amount` корректно даёт `<0.000001` и группировку.
- **Отказ провайдера.** Цикл не падает, ошибка видна, водяной знак не двигается; цены отдельно и не ломают индексацию; inspector без receipt показывает «нет данных», а не 0.
- **Миграции.** Транзакционные, с версией в той же транзакции, только вперёд.
- **Basic auth.** Оба поля сравниваются за константное время; статика тоже закрыта; `/healthz` при auth ничего не раскрывает.
- **XSS.** Jinja autoescape; символы токенов (контролируются атакующим) в JS-контекст не попадают, `|safe` только на литералах.
- **Зависимости.** Минимальный набор, закреплённые версии, pip-audit чист.
- **Docker.** Non-root, loopback-порт, понятные ошибки конфигурации (директория вместо файла, права 600).
- **Тесты.** 323 быстрых офлайн-теста с записанными payload'ами; хорошая основа для регрессий по всем находкам выше.

### 5.1 Подтверждённые UX-дефекты

#### U-01 · P1 · При потере связи с сервером статус остаётся «зелёным»
- **Где:** `_status.html` (опрос `every 5s`), `_behaviour.html` (нет обработчика `htmx:sendError`); «Ns ago» рендерится сервером и на клиенте не стареет.
- **Воспроизведение:** открыть `/`, остановить сервер (или отключить сеть) и подождать 40 с.
- **Фактически:** точка зелёная (`status--ok`), подпись «Ethereum · #23,800,000 · 2s ago», в консоли 42 `htmx:sendError`, на странице ничего (`L_server_killed_40s_1440.png`, `…_390.png`).
- **Ожидается (README):** «never presents stale data as current».
- **Решение:** при `htmx:sendError`/`responseError` на `#topline` перевести статус в `status--error` с текстом «connection lost · last update HH:MM»; хранить `data-updated` (unix) и пересчитывать «Ns ago» на клиенте раз в секунду; после восстановления — обычный опрос.
- **Проверка:** Playwright: остановить сервер → через ≤ 10 с статус красный; запустить снова → зелёный.

#### U-02 · P1 · На телефоне шторка «N more assets» открывается пустой
- **Где:** `app/web/static/app.css:1448` — правило `.holdings > .holding:not(.holding--compact){display:none}` (специфичность 0,3,0) перебивает `app.css:1451` `.holdings--all > .holding{display:block}` (0,2,0).
- **Воспроизведение:** ширина ≤ 860, портфель больше 3 активов, нажать «29 more assets ›».
- **Фактически:** заголовок и строка про dust, список нулевой высоты, все 31 `li` с `display:none` (`M_holdings_sheet_390_v2.png`).
- **Решение:** ограничить правило 1448 селектором `.holdings:not(.holdings--all) > …`.
- **Проверка:** тест в `test_web.py` ловит только разметку, поэтому нужен Playwright-смоук «шторка содержит ≥ 1 видимый `li`».

#### U-03 · P1 · Горизонтальное переполнение на ширине ≤ 430 px
- **Замер:** `scrollWidth` 518 px на 430/390/360/320 (в отдельных состояниях 440). На 1440–768 переполнения нет.
- **Причины:**
  - сумма NMT `1,000,000,000,000,000,000,000,000,000,000` (332 px) вместе с фиатом;
  - `.pair` у перевода между своими кошельками с длинным именем не переносится.
- **Последствие:** при мобильной эмуляции layout viewport расширяется до 518 px, и фиксированная шторка scope уезжает за нижний край: видимы y=792–1196 при высоте 900 (`B_scope_sheet_390.png`, `A_overflow_nmt_390.png`, `A_overflow_pair_390.png`). Как это выглядит на реальных устройствах (pan или zoom-out), не проверялось.
- **Решение:** в блоке `≤860` задать `.pair`, `.amount` `min-width:0` плюс ellipsis для имён, сокращение абсурдных сумм (U-05), `overflow-x: clip` на `.app` как страховку.
- **Проверка:** Playwright: на всех 8 ширинах `scrollWidth <= innerWidth`.

#### U-04 · P1 · Суммы обрезаются многоточием, порядок величины теряется
- **Где:**
  - строка холдингов `app.css:303` (`.holding__amount`): «USDC 10,001,74…», символы «GRAI…», «MEGA…»;
  - на 1024 px с открытым инспектором: «123,456…», «1,000,0…», «$1…», «ET…»; кошельки «Tre…», «Pa…»; «Uniswap: Universal Route» обрезан без многоточия (`J_summary_zoom_1440.png`, `D_insp_multi_nofee_1024.png`).
- **Почему важно:** в денежном логе «1,000,0…» может означать любую величину. Это хуже, чем отсутствие числа.
- **Решение:**
  - число никогда не обрезать: сначала укорачивать символ, при нехватке места переходить на компактную запись («10.0M USDC») с точным значением в `title`;
  - на 861–1100 px с открытым инспектором скрывать колонку counterparty или wallet, либо показывать инспектор поверх таблицы, а не сжимать её.
- **Проверка:** Playwright: ни у одного `.num` нет `scrollWidth > clientWidth` на 1024–1440 px.

#### U-05 · P1 · Защита от «неправдоподобной» котировки работает только для итога
- **Где:**
  - строки ленты (`build_activity`): NMT показан как «$420,000,000,000,000,000,000,000,000,000» по умолчанию, потому что он оценён и поэтому не считается ни dust, ни unverified;
  - `_holdings.html:9`: в мобильной шторке нет класса `holding--excluded`, NMT идёт без зачёркивания с полной суммой;
  - на десктопе excluded-холдинг стоит первым.
- **Решение:**
  - передавать признак excluded/implausible в модели строки и холдинга;
  - фиат зачёркивать или ставить «—» с `title="quote not credible"`;
  - excluded показывать последним;
  - в ленте такие строки считать unverified.
- **Проверка:** тест рендера строки и холдинга с excluded-активом.

#### U-06 · P1 · Строки ленты и инспектор недоступны с клавиатуры
- **Замер:**
  - 0 из 51 `tr[data-activity]` получают фокус, ролей нет; инспектор открывается только по `click` (`_rows.html:20-24`);
  - после открытия фокус остаётся на `<body>`, при закрытии не возвращается;
  - Escape закрывает инспектор (это работает).
- **Мобильная версия:** шторки scope и инспектора без `role="dialog"`/`aria-modal`/`inert`, Tab уходит в контент под затемнением.
- **Решение:**
  - в ячейку времени или суммы добавить настоящую `<button>`, которая открывает `/tx/{id}`;
  - при открытии переводить фокус на `.insp__close`, при закрытии возвращать его на строку;
  - на ≤ 860 px обе шторки делать модальными: `inert` на `.app`, перенос и удержание фокуса.
- **Проверка:** Playwright: Tab → Enter открывает инспектор, фокус внутри, Escape → фокус на исходной строке.

#### U-07 · P1 · Контраст и базовая доступность (axe-core)

Нарушения axe-core по состояниям:

| Состояние | Узлы | Основное |
| --- | --- | --- |
| Дашборд 1440 | 252 | 238 color-contrast, 13 region, 1 empty-table-header |
| Дашборд 390 | 166 | 157 contrast, **1 critical `select-name`** |
| Инспектор 1440 | 218 | + heading-order |
| Форма кошелька | 5 | |

Пары цветов:
- `--muted` #6e7986 на #0b0d10 — 4.39:1 (121 узел, чуть ниже 4.5:1);
- `--dim` #55606c — 3.03:1 (70 узлов);
- хеш транзакции в покое — 2.1:1 (43 узла);
- подписи формы 10px — 2.83:1.

Прочие нарушения:
- нет `aria-live`/`role="status"`, поэтому error и stale никогда не объявляются;
- у мобильного `<select>` актива нет имени (подпись скрыта);
- пустой `<th class="cell-fill">`;
- у инспектора `h3` идёт сразу после `h1`;
- фокус-кольцо — тонкое системное по умолчанию.

Решение:
- поднять `--muted` примерно до #7a8694 и `--dim` примерно до #6b7682, хеш в покое — до уровня `--dim`; характер тёмного терминала при этом сохраняется;
- добавить `role="status"` на `.status__detail` и `aria-label="Asset"` на select;
- глобально задать `:focus-visible { outline: 2px solid var(--accent) }`.

Проверка: axe в Playwright-смоуке, ноль нарушений serious/critical.

#### U-08 · P2 · Строка «N noisy transfers hidden» не обновляется при смене scope из сайдбара или шторки
- **Где:** ссылки кошельков и групп делают `hx-get="/activity"` напрямую (`_wallets.html:4,51,66`). Событие `filtersApplied`, которое слушает `#dust-note`, отправляет только обработчик формы фильтров.
- **Воспроизведение:** «All» → клик по Whale #1. Строка по-прежнему «46 noisy … 3 dust · 43 unverified», хотя сервер для этого scope возвращает пустую строку (`B_wallet_watched_1440_fold.png`).
- **Решение:** отправлять `filtersApplied` из `afterFilterChange()` (`_behaviour.html:63`).
- **Проверка:** Playwright: смена кошелька меняет текст строки.

#### U-09 · P2 · Поиск не находит встроенные имена адресов
- **Где:** `app/db.py:519-524` ищет только по `labels` из конфига.
- **Воспроизведение:** «Uniswap: Universal Router» есть в десятках строк, но `?q=Uniswap` возвращает 0. Метки из конфига («Binance hot») ищутся.
- **Решение:** перед запросом сопоставлять термин с `known_addresses` в Python и добавлять `OR from/to_address IN (…)`.
- **Проверка:** тест `?q=uniswap` возвращает строки с роутером.

#### U-10 · P2 · Поиск не реагирует на вставку и на очистку крестиком
- **Где:** `index.html:23`, триггер `keyup changed … from:#search`.
- **Фактически:** после вставки мышью или очистки нативным × лента не меняется до blur.
- **Решение:** `input changed delay:300ms from:#search, search from:#search`.

#### U-11 · P2 · Ошибки формы «Add wallet» не привязаны к полю
- **Фактически:** после неверного checksum или дубля фокус возвращается на Name (`autofocus`); нет `aria-invalid`, `aria-describedby`, `role="alert"` (`I_form_badchecksum_390.png`).
- **Решение:** сервер ставит `aria-invalid` и `autofocus` на поле с ошибкой; у `.sheet__error` добавить `id` и `role="alert"`.

#### U-12 · P2 · Подгруженная история сбрасывается автообновлением (Partly)
- **Воспроизведение:** долистать ленту до конца (284 строки), вернуться наверх, подождать ~35 с. Остаётся 50 строк.
- **Где, вероятно:** `_behaviour.html:313-318` сбрасывает `dataset.paged` на любом запросе не от `#feed-more`, включая опросы `/status` каждые 5 с и `/summary` каждые 30 с. Сброс после `/status` замерен, полная цепочка не доказана.
- **Решение:** сбрасывать флаг только для запросов с целью `#feed-body`, которые не являются пагинацией.

#### U-13 · P2 · Неверные тексты в деградированных и пустых состояниях
- **Stale:** выводится «no successful sync for 3h ago», потому что `format.py` в `build_status` передаёт результат `relative_time`, а тот уже добавляет «ago» (`K_stale_1440_fold.png`).
- **Zero:** синхронизация успешна, активности нет, но лента говорит «If the app just started, the first sync is still running» при зелёном статусе, а портфель — «no valuation yet» (`K_zero_1440_fold.png`).
- **Решение:** формулировки ветвить по `status.backfilling`; в stale-тексте писать «for 3h».

#### U-14 · P2 · Мелкие дефекты вёрстки
- Строка комиссии в инспекторе визуально слипается: «0.000252 ETH$0.79» (`D_insp_failed_fee_768.png`).

### 5.2 UX-недостатки (поведение верное, но решение спорное)

- **W-1.** «Load 90 more days» без нового результата возвращает ту же кнопку, изменив только номер блока. Стоит написать: «nothing between Aug 17 and May 19».
- **W-2.** Если комиссия неизвестна, блок Fee просто отсутствует. Лучше тусклая строка «Fee — unavailable», чтобы «неизвестно» отличалось от «не бывает».
- **W-3.** Значение строки ленты считается по **текущей** цене. Подписи «at current price» нет ни в заголовке, ни в тултипе. Это легко принять за стоимость на момент перевода (см. также D-16).
- **W-4.** На мобильном активные фильтры уезжают вместе со скроллом. Нужен маленький индикатор «filtered» в sticky-баре.
- **W-5.** Заголовки дней на десктопе не sticky: в середине списка у строки «19:55» не видно даты.
- **W-6.** После «Add wallet» нет подтверждения, а новый кошелёк показывает «—» без состояния «indexing…». Select «Chain» с единственным вариантом — лишнее поле.
- **W-7.** Текст ошибки провайдера выводится как есть, технической строкой. Нужен короткий человеческий текст, а исходный — в `title` (после исправления D-01).
- **W-8.** Нет `color-scheme: dark`, поэтому нативные контролы и скроллбары местами светлые. Светлой темы нет. Это нормально для продукта, но `color-scheme` стоит указать.
- **W-9.** Опрос `/status` каждые 5 с продолжается в скрытых вкладках. Квоту провайдера это не расходует, но нагружает сервер с каждой открытой вкладки.
- **W-10.** Пустой `wallets:` запрещён валидацией, поэтому поставить приложение и добавить кошельки только из UI нельзя. Ветка «No wallets configured.» в `_wallets.html` недостижима.

### 5.3 Что в UI работает хорошо — не трогать

- Автообновление: новые строки подсвечиваются; фильтры, позиция скролла и открытый инспектор переживают обновление (`F_refresh_highlight_1440.png`).
- Sticky top bar, фильтры и шапка таблицы на 1440/1280/1024 без зазоров; отступы измеряются в рантайме.
- Форматирование: честное `<0.000001 ETH`; «—» для неоценённого; «valuation off» и «N unpriced» различаются.
- Итог при scam-токене верный ($14.05M, а не квадриллионы), пометка «NMT excluded».
- Группировка по транзакциям («↳ 4 more transfers»), дни Today/Yesterday в нужной TZ, пагинация: 284 строки за 5 страниц без дублей строк и заголовков.
- Сообщения валидации адреса точные: EIP-55, длина, дубль.
- Состояния error и stale заметные; возраст цен становится янтарным.
- Escape закрывает слои изнутри наружу; `prefers-reduced-motion` учитывается.
- Мобильная информационная архитектура в целом (лог из двух строк, scope в top bar) удачная; проблемы точечные, их стоит чинить без редизайна.
