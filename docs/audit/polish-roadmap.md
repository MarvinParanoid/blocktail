# Blocktail: polish roadmap

*По итогам [product-audit.md](product-audit.md). Концепция не меняется: read-only, один процесс, SQLite, сервер рендерит страницу, HTMX. Новой инфраструктуры нет.*

Правила для всех этапов:
- один этап — одна ветка, один PR;
- каждый этап можно выпустить отдельно;
- каждое исправление сопровождается регрессионным тестом, который падает до исправления;
- `pytest` зелёный, `ruff --select F,E9` чистый.

Этапы S0–S3 закрывают корректность и безопасность, S4–S7 — UI, S8–S9 — эксплуатацию.

## S0. Секрет не утекает · P0

**Сделать**
- `alchemy.py:_rpc` и `prices.py:_request`: в сообщение ошибки не включать `str(httpx_exc)`. Формат: `"{method}: HTTP {code}"` или `"{method}: {ExceptionClass}"`.
- Страховка: функция `redact(text, settings)`, которая вырезает ключ и всё после `/v2/`. Применяется в `db.record_failure` и в фильтре логгера.
- 401 и 403 после исчерпания ретраев показывать понятным текстом: «provider rejected the API key».

**Готово, когда** ни HTML, ни `/status`, ни `/api/status`, ни лог не содержат ключа при 400/401/404, `ConnectError` и таймауте.

**Тесты:** `httpx.MockTransport` с этими ответами; `caplog`; расширить `test_is_read_only_and_leaks_no_secrets` состоянием ошибки.

**Риск:** низкий. Ошибки станут лаконичнее; исходный текст без URL можно оставить в DEBUG-логе.

## S1. Честный итог портфеля · P1

**Сделать**
- Одна функция оценки для сайдбара и панели (сейчас логика дублируется в `build_wallets` и `build_portfolio`).
- Итог считается только по видимым и не-excluded активам (D-03).
- Неизвестные decimals обозначаются `None`, а не 0. Такой актив не оценивается и попадает в «unpriced».
- Неудача `getTokenMetadata` не кешируется.
- Для токенов из вендоренного списка decimals берутся из списка (D-04).
- Признак `excluded` передаётся в модели строки ленты и холдинга, чтобы UI в S5 мог его показать (U-05).

**Готово, когда:**
- impostor за $5k не меняет итог;
- WBTC после 503 на метаданных не стоит триллионы, а после восстановления провайдера получает верные decimals без рестарта;
- сумма в сайдбаре равна сумме в панели во всех сценариях.

**Тесты:** три сценария из аудита (D-03, D-04) плюс property-тест: сумма в сайдбаре равна сумме в панели на случайных наборах.

**Риск:** средний, затрагивает видимые цифры. Сверить с текущими данными на VPS до и после (см. «Требует решения», п. 3).

## S2. Удалённый кошелёк по-настоящему удалён · P1

**Сделать**
- `relink_accounts()` привязывает только активные аккаунты.
- `add_account` и `apply_watch_config` вызывают relink при восстановлении аккаунта.
- `known_event_keys` для prune ограничен событиями, где одна из сторон — активный аккаунт.
- Строки, где ни одна сторона не активна, не показываются в «All».

**Готово, когда:**
- add → sync → remove: лента, IN/OUT и `sent_asset_ids` про кошелёк не знают, следующий цикл ничего не удаляет;
- после re-add строки возвращаются без нового бэкфилла.

**Тесты:** сценарии D-02 и D-07 для UI-кошелька и для config-кошелька.

**Риск:** средний. Relink выполняется при каждом старте; на большой базе проверить время (в аудите 200k строк — без замера relink, замерить отдельно).

## S3. Индексатор: один цикл за раз, частичный успех · P1/P2

**Сделать**
- `asyncio.Lock` в `Indexer.run_once` (single-flight).
- `/history/older` только записывает `requested_from_block` и будит цикл через `asyncio.Event`. В ответе приходит строка «indexing older history…», статус отражает прогресс.
- Опционально: потолок глубины в настройке.
- Сбой балансов не мешает продвинуть водяной знак. Хранится отдельный `balances_error`, который показывается янтарным, а не как error (D-08).
- Prune по всему пересканированному диапазону: `prune_from = from_block` (D-09).

**Готово, когда:**
- два параллельных POST и фоновый цикл дают провайдеру ровно один цикл;
- эндпоинт отвечает меньше чем за 1 с;
- при падающих балансах `last_synced_block` растёт;
- orphan после простоя удаляется.

**Тесты:** сценарии D-05, D-08, D-09 из аудита; тест на lock с медленным `FakeProvider`.

**Риск:** средний, это ядро. Изменения ограничены `sync.py`, `routes.py` и одной миграцией (колонка `balances_error`).

## S4. Честный статус в браузере · P1

**Сделать**
- `htmx:sendError` и `responseError` на `#topline` переводят статус в «connection lost · last update HH:MM».
- `data-updated` содержит unix-время, «Ns ago» пересчитывается на клиенте каждую секунду.
- `role="status"` на строке деталей.
- Тексты: «no successful sync for 3h»; пустое состояние ветвится по `backfilling`.
- Короткий человеческий текст ошибки провайдера, исходный текст в `title`.

**Готово, когда** через 10 с после остановки сервера статус красный, а после старта снова зелёный.

**Тесты:** юнит-тест `build_status`; Playwright-сценарий «kill → red → restart → green».

**Риск:** низкий.

## S5. Мобильная вёрстка и числа · P1

- `scrollWidth ≤ innerWidth`;
- ни у одного `.num` нет переполнения;
- шторка холдингов не пустая;
- axe: 0 нарушений serious и critical (включается после S6).

**Сделать**
- Исправить селектор `app.css:1448` (U-02).
- `min-width:0` и перенос или ellipsis у имён в `.pair`; для чисел только компактная запись, точное значение в `title` (U-03, U-04).
- На 861–1100 px с открытым инспектором скрывать колонку counterparty.
- Отображение excluded: зачёркнуто или «—», в конце списка, класс в `_holdings.html` (U-05).
- Тап-зоны не меньше 44 px для scope, закрытия инспектора, «···», сегментов и поиска; scope-кнопка в одну строку (U-14).
- Пробел в строке комиссии; `color-scheme: dark`.

**Готово, когда** смоук зелёный на всех ширинах, а скриншоты 390 и 1024 вручную сверены с аудитом.

**Риск:** средний, визуальный. Мобильная архитектура (лог из двух строк, scope в top bar) не меняется, только точечные правки CSS.

## S8. HTTP и контейнер · P2

**Сделать**
- Middleware заголовков: CSP с `frame-ancestors 'none'`, `nosniff`, `Referrer-Policy: no-referrer`. Сначала CSP с `'unsafe-inline'`, потому что сейчас есть inline-скрипты и `onclick`; ужесточать отдельно.
- CSRF принимает только `same-origin` и `none`.
- `/healthz` отдаёт `sync_state` и возраст последнего успеха даже при auth; опционально `?strict=1` → 503.
- Compose: `read_only`, `tmpfs: /tmp`, `cap_drop: [ALL]`, `no-new-privileges`, `mem_limit`.
- CI:
  - `permissions: contents: read`;
  - actions закреплены по SHA;
  - `pip-audit`;
  - единая версия ruff;
  - smoke-старт образа с недоступным провайдером → `healthz` 200;
  - Dependabot для pip, actions и docker.

**Готово, когда:**
- тест заголовков проходит;
- в консоли браузера нет нарушений CSP;
- контейнер стартует с `read_only`;
- CI зелёный.

**Риск:** CSP может сломать htmx и inline-обработчики. Проверять в браузере, выкатывать отдельным коммитом.

## Чего не делать

- Не менять мобильную информационную архитектуру и не возвращать внутреннюю область прокрутки: ARCHITECTURE объясняет, почему от неё отказались.
- Не трогать идентичность событий (`uniqueId`, upsert), keyset-пагинацию, арифметику на `Decimal`, транзакционные миграции.
- Не выводить forgery-targets из token list и не скачивать list в рантайме.
- Не делать `/healthz` красным при сбое провайдера для Docker healthcheck.
- Не добавлять очередь, Redis, второй процесс-воркер, ORM или SPA-фреймворк ради S3 и S5: хватит `asyncio.Lock` и `Event`.
- Не расширять продукт: multi-chain, подключение кошелька, NFT, P&L, алерты, аккаунты.
